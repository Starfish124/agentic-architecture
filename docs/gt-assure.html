GT Assure

AI-assisted control testing and PBC management for an assurance practice. Everything runs on the consultant's machine; no client evidence leaves it.

The system compresses the mechanical part of control testing — retrieval, first-pass assessment, citation, PBC administration — and leaves the judgement with a named human who approves every conclusion before it can be exported.

Constraints, not aspirations

GuaranteeHow it holds
Fully localAll inference via Ollama on the machine. No external call anywhere in the data path. Works offline after setup.
Framework-agnosticNIS2, DORA, ISO 27001, DigiD, client-specific — loaded as configuration files, never hard-coded.
Human in the loopThe system drafts, a named consultant approves, nothing exports unapproved. It never contacts a client.
AuditableAppend-only log of every analysis: model + version, inputs, evidence consulted, output hash, reviewer.
Pinned modelOne generation tag per run. Config records the expected digest; startup verifies and warns on mismatch.
Synthetic data onlyShips with a full fictional engagement, so the demo never needs real client data.

Two steps exist because of a specific failure. Retrieval returns whole documents in page order rather than the closest paragraph, because the incident plan's severity matrix and its named crisis roles sit on different pages — judging the control on whichever page embedded closest manufactures false gaps. And if retrieval returns nothing, the second model call never happens, because a model with no evidence in front of it will answer from general knowledge about what such a control usually looks like.

Evidence is found literally, not semantically. "Which passages mention ticket 14721" is a text question; a ticket number carries almost no embedding signal, so the correct document repeatedly fell outside top-k while unrelated ones ranked above it.

Errors run conservative: the tool over-refers to the reviewer rather than passing items silently. That is the right direction for assurance work, and it is not accuracy.

Pitch the cited reasoning, not the label. That is the demo instruction and it is also the honest description of what an 8B is good for.

Walkthroughs

A transcript becomes the process description and a flowchart. The transcript is numbered by line and every extracted step must cite the line it came from; a step citing nothing is discarded and counted. Exact rather than fuzzy on purpose — a line number either resolves to something somebody said or it does not. Control references are whitelisted against the control's own identifiers, steps are renumbered by position because the model's numbering drifts, and the flowchart is laid out deterministically so two workpapers for the same process can be compared.

Push on this

  • Approval is enforced by writing the export file only at approval time. Elegant, but the guarantee lives in a file's existence rather than in a check I can point at.
  • The 8B's attribute-level instability is measured but not bounded. Unknown on a real population an order of magnitude larger.
  • The audit chain is append-only JSONL on the same disk as the evidence. Tamper-evident, not tamper-proof.
